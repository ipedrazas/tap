# tapctl reference

Generated by `task docs:cli` from `cmd/tapctl/commands.go`; do not edit by hand.

Every command prints this help with `tapctl help <command>` or `tapctl <command> -h`. `tapctl --version` (or `tapctl version`) prints the version, git commit and build date.

Exit codes: `0` ok, `1` error or failed check, `3` (`diff` only) permissions widened.

## Authoring

### `tapctl new`

```text
Scaffold a new agent bundle that validates as-is

Usage:
  tapctl new [flags] <name>

Writes agents/<name>/ from the runner-node or runner-python scaffold, pinned to
the current curated runner digest from platform.yaml. Replace the example tool.

  tapctl new exchange-agent --runner runner-node --description "Converts currencies"

Flags:
  -agents-dir string
    	where agent bundles live (default "agents")
  -description string
    	one-sentence description (max 200 chars) (default "Describe what this agent does in one sentence")
  -owner string
    	owning team (default "platform")
  -platform string
    	platform config (default "platform.yaml")
  -runner string
    	runner-node or runner-python (default "runner-node")
```

### `tapctl validate`

```text
Check agent.yaml against the schema and rules 0-6, 8-12

Usage:
  tapctl validate [flags] <agent-dir>

Loads agent.yaml, fixtures and MCP snapshots and applies every validation rule
(see docs/implementation-plan.md and .claude/skills/new-agent/reference/spec.md).
Prints one line per finding and exits 1 if there are any.

Flags:
  -platform string
    	platform config (default "platform.yaml")
```

### `tapctl diff`

```text
Permission diff against a base version (rules 7, 11)

Usage:
  tapctl diff [flags] <agent-dir>

Compares tools, effects, secrets, egress hosts, MCP servers and effectsPolicy
with a base version. "+" lines widen permissions, "-" lines narrow them.

Exit codes: 0 no widening, 1 agent.yaml changed without a version bump,
3 permissions widened (human review required; expected for a new agent).

  tapctl diff --base git:origin/main agents/weather-agent
  tapctl diff --base oci:registry.hiddenfield.dev/agents/weather-agent:0.1.0 agents/weather-agent

Flags:
  -base string
    	base version: git:<ref>, oci:<image-ref>, or a path to agent.yaml; empty means a new agent
  -platform string
    	platform config (default "platform.yaml")
```

## Building and deploying

### `tapctl bundle build`

```text
Build the bundle image (reproducible); --push to upload it

Usage:
  tapctl bundle build [flags] <agent-dir>

Validates, then builds the OCI image the cluster mounts as an image volume.
Identical sources give identical digests. With --push the image goes to
<registry>/agents/<name>:<version>; version tags are immutable. --dev pushes to
the moving :dev tag instead.

Flags:
  -dev
    	with --push, use the moving tag :dev instead of the immutable version tag
  -digest-file string
    	write the pushed digest reference to this file
  -platform string
    	platform config (default "platform.yaml")
  -push
    	push to <registry>/agents/<name>:<version>
```

### `tapctl render`

```text
Print the Kubernetes manifests for a pushed bundle

Usage:
  tapctl render [flags] <agent-dir>

Output contains no secret values and can be committed to a GitOps repo. --test renders the fixture Job instead.

Flags:
  -bundle string
    	pushed bundle reference, by digest
  -bundle-file string
    	read the bundle reference from this file
  -platform string
    	platform config (default "platform.yaml")
  -test
    	render the fixture-test Job instead of the runtime manifests
```

### `tapctl mcp snapshot`

```text
Pin allowlisted MCP tool schemas into mcp/<server>.tools.json

Usage:
  tapctl mcp snapshot [flags] <agent-dir>

Connects to each declared server and pins the allowlisted tools' descriptions and input schemas. With --check, reports drift instead of writing (exit 1 on drift).

Flags:
  -check
    	compare the live schemas with the pinned ones instead of writing
  -env-file string
    	KEY=value secrets for MCP auth (default .env.<agent>)
```

## Cluster

### `tapctl agent ls`

```text
List the agents running in the cluster

Usage:
  tapctl agent ls [flags]

Reads agent namespaces through your kubeconfig and prints one line per agent:
readiness, version, model, tool counts, restarts, age and URL.

  tapctl agent ls
  tapctl agent ls -o json

Flags:
  -context string
    	kubeconfig context (default: current)
  -kubeconfig string
    	path to kubeconfig (default: $KUBECONFIG or ~/.kube/config)
  -o string
    	output: table, wide or json (default "table")
```
